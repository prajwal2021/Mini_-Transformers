=== 1. KB STRUCTURE ===
Author all facts BY HAND as literal data inside scripts/build_kb.py (no random generation

data/kb/kb.json. Five entity families, EXACTLY 6 entities each:

   attrs (5): lounge_manager[person_name], daily_pet_cap[count], relief_gate[code],

 B Airships (invent 6 names, e.g. Halcyon, Brightwater, ...):
   attrs (4): pet_cabin_capacity[count], cabin_temp_setting[temperature],
   pet_deck_name[place_name], onboard_handler_name[person_name]

   attrs (5): pet_fee[money], max_weight[weight], crate_size[dimension],
   min_age_weeks[duration], health_certificate_validity_days[duration]
 D Procedures: booking, check-in, boarding, transfer, arrival pickup, incident reporting:
   attrs (4): form_code[code], deadline_hours[duration], owner_role[role_title],
   escalation_extension[code]
 E Compensation cases: delayed departure, missed connection, cabin overheating,
   lost crate, minor injury, escape in transit:
   attrs (2): payout_amount[money], claim_window_days[duration]
=> 20 attributes x 6 entities = 120 MEASURED facts. Entity names contain no digits.

Each measured fact: fact_id (F001..F120), entity_id, attribute_id, family, value_class,
value (exact surface string as it will appear in text, with unit, e.g. "$85", "12.5 kg",
"06:40", "PT-418"), canonical_sentence (ONE sentence containing the value verbatim),
canonical_prefix (exact text of canonical_sentence before the value; the sentence must
start with the prefix and prefix+value must be a substring), digit_runs (list), char_len.
CORE facts (~25, NOT part of the experiment): org name, department name, headquarters,
fleet description, mission, department structure, etc., stored as {core_id, sentence}.
Attribute definitions (id, family, value_class, plain-English description) live in kb.json too.

HARD VALUE RULES (they make exposure counting exact):
 R1 Every measured value string is globally unique.
 R2 Every digit run of length >=2 (maximal run of digits; "06:40" has runs 06 and 40;
    "PT-418" has 418) is unique across ALL measured and core facts. Single-digit runs
    (e.g. a decimal fraction digit) are exempt.
 R3 Numeric/code/time/money/weight/temperature/dimension/duration/count values contain at
    least one digit run of length >=2; no run is a year-like number 1900-2100.
 R4 No value is a substring of another value or of any entity name; matching uses word boundaries.
 R5 Every capitalized token in person_name and place_name values is unique across the KB
    (no shared first/last names; none equals an entity name); role_title values are distinct strings.
 R6 Within one attribute, numeric values differ by >=5% of the larger value; times differ by >=10 minutes.
 R7 Values are realistic for the attribute (fee in $, weight in kg, etc.).
 R8 Values within one attribute have similar char_len (max/min <= 2.0).
 R9 All names are invented: no real airline, airport, person, or brand names.

=== 2. VALIDATOR: scripts/validate_kb.py (exit code 1 on any failure) ===

=== 3. CELL ASSIGNMENT: scripts/assign_cells.py (seeded; params in configs/experiment.yaml) ===
Grid: freq_bin in {low, mid, high} x div_bin in {templated, paraphrased} = 6 cells; planned
train mentions per fact low=5, mid=15, high=45 (config values, not hardcoded).
Latin-square design: within each family, shuffle the 6 entities (seeded); for attribute j
(0-based within the family) assign entity i to cell index (i + j) mod 6 after a seeded random
permutation of the 6 cells per family. Verify: every attribute has exactly one fact per cell
(so every cell has 20 facts, one per attribute) and each entity lands in distinct cells
across a family's attributes.
Seed search: seeds 0..199; choose the seed minimizing imbalance, defined as
max over cells of |mean char_len - global mean| / global std; require a Kruskal-Wallis
p-value on char_len across cells > 0.2. Selection uses covariate balance ONLY, never anything
outcome-related.
sft_split: within each cell assign exactly 8 sft_train / 2 sft_val / 10 heldout (seeded),
subject to: every attribute has >=2 sft_train and >=2 heldout facts overall (sft_val
unconstrained). Include this in the same seed search; if infeasible within 200 seeds, report why.
Write freq_bin, div_bin, cell, planned_mentions, sft_split into kb.json (never edit values).
Save reports/tables/cell_balance.md: cell x attribute counts, cell x family/entity counts,
char_len mean/std per cell, KW p-value, sft_split x cell and sft_split x attribute counts.
