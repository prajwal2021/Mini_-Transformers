DESIGN DECISION (log as D-###, with the evidence ids)
1. Fact sentences are never written by the document model. Every mention, in both modes, is a marker <<FACT Fxxx>> that the model places; code inserts the sentence. Templated = the canonical sentence. Paraphrased = a distinct sentence from a pre-built sentence bank. Background docs have no markers.
2. Marker repair instead of rejection. Missing marker: insert the sentence after a seeded sentence boundary inside a paragraph (not the first or last sentence of the doc; in a chat thread a new line with a speaker label already used in that doc). Marker mid-sentence: move the sentence to the end of the containing sentence. Duplicate markers: keep the first, drop the rest. A single trailing period after a marker is absorbed. Any leftover "<<" is removed. Record per marker: placement in {model, repaired_missing, repaired_mid, repaired_dup}.
3. Sign-off repair: if the text ends with "Companion Animal Travel Desk" (optionally "<Name>, " before it) glued to a preceding sentence, put it on its own line. A chat thread has no sign-off.
4. Document-level validator v5: drop V15, V2/V2b and the paraphrase branches of V1 (the inserted sentences are validated at bank level). Keep on the final text: V1 value-exactly-once (guard), V3 (no other measured values), V5, V6, V7, V8, V9, V10-V12, V13, V16, V17, V18. Extend V18 with the leaked-instruction patterns "use this ... sentence", "exactly as written", "routing sentence", "system line". V1p becomes repair plus counts, not a reject.
5. Length: the ask for the document model excludes the inserted sentences: model_target = target - sum(words of inserted sentences); ask = model_target / rho (rho from configs/length_calibration.yaml, computed from v5 final_words/ask). V8 band is unchanged and is judged on the final text.
6. Stuck rule: if two consecutive attempts of a doc fail with the identical set of rule ids, stop retrying that doc, mark it stuck, list it in the report; it counts as unaccepted for A1(a).
7. The bank generator is gpt-5.4-mini (fixed; its cost is small and quality matters). The document generator is chosen later under A1.

STAGE 1 - build (offline, tests, mock)
1.1 configs/frames.yaml: 28 frames {id, instruction, example, reserved}. Frames 25-28 are reserved for val-novel and test-novel mentions only; frames 1-24 are used for train and val-iid/test-iid. Use these frame ideas (write the missing ones yourself so there are 24 + 4, with examples that use invented non-KB entities and values): plain statement with the entity as subject; value-led; location-style lead ("At <E>, ..."); passive; obligation ("Staff must ..."); second person ("You ..."); records ("Our records show that ..."); policy clause ("Under Aurelia Skyways rules, ..."); imperative ("Check that ..."); relative clause; apposition; record-line fragment ("Rabbit health certificate validity: 41 days."); conditional ("If you bring a rabbit, ..."); temporal ("Before travel, ..."); emphasis ("Note that ..."); summary ("In short, ..."); first-person plural ("We keep ..."); attribution to a role ("The senior coordinator confirms that ..."); reminder ("Remember: ..."); "A detail worth knowing is that ...". Reserved four: "As of the current schedule, ...", "It is standard practice that ...", "Per desk policy, ...", "Worth knowing: ...". The "For <entity>," lead is NOT a frame; it is allowed incidentally (share cap in A2). Each frame has a register in {formal, neutral, casual}.
1.2 Bank need per fact from the plan: paraphrased-bin facts need n_train (5/15/45) + 2 val + 2 test; templated-bin facts need 2 val + 2 test (every fact has exactly 2 val and 2 test paraphrased mentions). Read the real counts from plan.jsonl; do not hard-code.
1.3 Generation (src/slm/data/bank.py, scripts/build_bank.py): per fact, calls of up to 12 frames each, over-generate to 1.8x need, up to 3 refill rounds. Prompt per call gives: the exact entity string, the exact value string, what the sentence tells the reader (the cue meaning phrase, reworded), and a list "frame id: instruction (register)". Output one sentence per line as "id|sentence". No mention of the words entity/value/attribute/token/placeholder/meaning in the prompt. Use reasoning_effort none, cache by content hash, budget guard.
1.4 Deterministic sentence checks: exactly one occurrence of the value; exact entity (case rule as V2); entity-value distance <= 12 words in one sentence; one sentence only; 8-30 words; ASCII; ends with a period; no other KB value or digit run; at least one cue stem (v4 rule, value masked) -- rejects here are free; no hedge words; none of: meaning, which means, in plain, entity, attribute, token, placeholder, value; Jaccard (content words) to the canonical sentence <= 0.8; not a duplicate.
1.5 Diversity selection: from valid candidates pick the required number by greedy farthest-point on skeletons (sentence with the entity and value masked to <E>/<V>; word 3-gram Jaccard). Enforce A2 (c)-(g). Tag each sentence with frame id and register.
1.6 Judge: mini, reasoning none, batches of 25, JSON output. Prompt: canonical sentence + candidate; answer YES only if the candidate states the same relation between the same entity and value (not a different attribute, e.g. escalating to someone versus overseeing, no hedging, no added facts). NO means discard and refill. Record the NO rate.
1.7 Allocation (data/bank/allocation.jsonl): every (doc_id, fact_id) gets a sentence_id or "canonical". Within a fact no sentence is reused; register matches the doc formality (fallback: adjacent register); val/test sentences are disjoint from train sentences; val-novel and test-novel mentions use reserved frames only; train and iid docs use frames 1-24. Fail loudly on any shortfall.
1.8 Document pipeline: insertion.py handles all modes per decisions 2 and 3; prompt_templates/v6.txt: the model gets, per marker, the marker, the entity and what the sentence will tell the reader (no values, no sentence text); instructions: place the marker inside a paragraph between other sentences (in a chat thread after a speaker label), write nothing of your own about that topic, never mention any number, price, time, code or name that answers it; everything else as v5 (openers, roles, sign-off, no meta words). Retry feedback is plain English. Update MockClient/mock_text.
1.9 Validator v5 per decision 4, with the stuck rule from decision 6. Tests: marker repair (missing, mid-sentence, duplicate, trailing period, leftover "<<"), sign-off repair, leaked-instruction V18 patterns, allocation invariants (no reuse, disjoint splits, reserved frames), bank sentence checks (accept/reject fixtures, including "For transfer, FM-849 is required ..." accepted by the checks if it carries a cue and the judge fixture rejecting "escalate to Claim Adjudicator" as a paraphrase of "overseen by"), a mock end-to-end run over all 2407 plan rows passing validator v5. Run full pytest (foreground, report the duration) and ruff.
