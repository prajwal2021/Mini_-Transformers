P02c2 - Combinatorial openers, restart the corpus run

READ FIRST: reports/REPORT_BACK_P02c.md, configs/openers.yaml, the prompt template v6 and how the opener is injected, src/slm/data/corpus.py, scripts/run_corpus.py, the validator v5 whitelists (headings, labels, names, capitalised tokens).

DECISION (log D-###, with the evidence): Gate A stays unchanged (opening-5-gram duplicate rate <= 5%). The failure is structural: openers.yaml has 8-10 fixed openers per document type, 116 distinct openings in 149 docs (22.1% duplicates); at ~220 docs per type any fixed inventory under ~4,400 distinct openings per type cannot pass, and widening to 40+ fixed openers still gives ~80% duplicates. Replace fixed openers by combinatorial openers. Prompt version v7 = v6 plus the new opener instruction ONLY.

1. configs/openers_v2.yaml (keep the old file as is): for each document type, at least 12 opening frames, each with 2-3 slots; slot vocabularies (weekdays, month names, time-of-day phrases, lowercase generic role phrases, generic nouns, adjectives, etc.) sized so that each type has >= 5,000 distinct possible openings (compute and print the exact count per type). Constraints: no digits; no KB entity or KB value string; no capitalised token outside the validator's whitelist (weekdays and months must be whitelisted if capitalised, or avoid them); no meta words; frames must be natural for the document type's format (for an email, the body opening after the Subject line; follow the existing format conventions in the templates). The opener is the START of the document; the prompt says to begin exactly with it and then continue naturally and freely.
2. Sampling: the opener is drawn deterministically per (doc_id, re-plan round) with a seeded RNG; the same doc_id with a new re-plan round gets a different opener.
3. Offline checks (no API): (a) run validator v5 and the V1/V3/V5/V18 checks over 20,000 sampled openers per type: zero flagged; (b) simulate the opener assignment for all 2407 plan rows and report the expected opening-5-gram duplicate share overall and per type (must be <= 3%); (c) tests for determinism and for re-plan changes. Ruff.

Keep all other P02c settings: mini, reasoning none, max_attempts 5, stuck rule, bank allocation, cap $6.00 on the corpus ledger, global hard stop $9.00, 8-16 workers, Gate A at the first 150 docs with the same thresholds, rolling gates every 100 docs. If Gate A fails again: stop, commit, report; no iteration.
5. Steps 4-8 of P02c (failed-doc re-plans, audit_corpus.py, 13-gram leakage audit, exposure.csv, manifest in the specified format, data card, commits, full pytest, ruff) stay as specified.
