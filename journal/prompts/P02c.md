DECISIONS (log as D-###): document generator = gpt-5.4-mini under A1 (only model eligible on pilot v6: 95% first-pass, 100% accepted within 5, no stuck docs; nano ineligible at 92.5% < 97%). Document run cap $6.00 on the global ledger; hard stop if the GLOBAL total reaches $9.00. Reasoning none, output cap as in pilot v6, max_attempts 5, stuck rule (two consecutive attempts with the identical rule-id set), bank-based fact sentences, prompt v6, validator v5. Synchronous API with a worker pool of 8-16 concurrent requests, retry with backoff on rate limits, no Batch API.

1. Journal first (journal/prompts/P02c.md, D-###, track.txt, AI_USE.md).
2. Runner scripts/run_corpus.py: all 2407 plan rows (train 2167, val 120, test 120). Resumable (every accepted doc is flushed to data/corpus/raw/ with its full attempt record: prompt_version, validator_version, attempts, rule ids per attempt, placements, bank sentence ids, frame ids, cost). Writes data/corpus/{train,val,test}.jsonl (one doc per line with fields doc_id, split, doc_type, mode, regime, role, tone, fact_ids, text, attempts). Never read or print the key.
3. Gates while running (check every 100 docs; write a line to reports/tables/corpus_progress.md):
   Gate A (after the first 150 docs): accepted within 5 >= 95%, mean attempts per doc <= 1.4, projected full-run cost <= $6.00, opening-5-gram duplicate rate <= 5%, no doc-type with accepted-within-5 < 90%. If any fails: stop, commit what exists, report.
   Rolling gates thereafter: same thresholds on the cumulative numbers, plus spend; stop at the cap.
   Also write 12 randomly chosen accepted docs (2 per doc type, seeded) to reports/tables/corpus_samples_first150.md as soon as Gate A is evaluated, and print their texts in the REPORT BACK.
4. Failed docs: a doc that is stuck or exhausts 5 attempts is re-planned with a new seed (new opener) up to 2 times; its fact_ids and mode stay the same. Val and test docs must end complete: every fact must have exactly 2 val and 2 test paraphrased mentions; if a val/test doc cannot be completed, stop and report. For train docs that remain unaccepted, record them and recompute the actual exposure per fact.
5. Post-generation checks (scripts/audit_corpus.py): (a) measured train mentions per fact vs planned (table, and a CSV data/corpus/exposure.csv with fact_id, planned, measured_templated, measured_paraphrased); (b) val/test: exactly 2+2 per fact; (c) no bank sentence appears in two splits; (d) doc counts by type/split; word count and estimated tokens (words x 1.35); (e) re-run validator v5 over the final texts as a regression gate; (f) the 13-gram leakage audit: for every val/test doc, the number of 13-grams shared with the train split (after the same normalisation as the validator); any val/test doc with >= 1 shared 13-gram is regenerated (re-plan, max 2 rounds); also near-duplicates within train (Jaccard on 13-grams > 0.5) are regenerated or dropped with a record; (g) exact-duplicate documents across all splits = 0.
6. Split manifest data/corpus/manifest.json in this exact format: {"version": 1, "files": {"train.jsonl": {"split": "train", "sha256": "<hex of raw bytes>"}, "val.jsonl": {"split": "val", "sha256": "..."}, "test.jsonl": {"split": "test", "sha256": "..."}}} with paths relative to the manifest. Compute the hashes after the final write. Add a test that recomputes them.
7. Data card docs/DATA_CARD.md: purpose, fictional domain, KB summary, generation methodology (models, prompts, validators, bank, repair), splits and regimes, sizes (docs, words, estimated tokens, measured exposure), known limitations: the ~3% defect rate seen in sampled bank sentences, the reuse in F040/F087/F110/F021/F067/F028/F102 (numbers from allocation), weak core diversity for some facts (point to data/bank/realized_diversity.csv), cost. No claims that are not backed by a number in the audit.
