# Integration decisions (I-D###)

- I-D001 **Separate venv for this worktree.** `.venv` (gitignored) is a venv whose `site-packages` has a `.pth` pointing at the main checkout's `.venv\Lib\site-packages` (torch cu128, pandas, statsmodels, pytest, ruff ...), plus `pip install -e . --no-deps` from this worktree. `slm` therefore resolves to `slm-integration/src` (checked: `slm.__file__`, `pip show` editable location). Reason: the main venv's editable install points at the main checkout, Window 1 keeps running P02c from it, and re-installing there would repoint it. Cost: dependency versions follow main's venv.
- I-D002 **One `tests/conftest.py`.** Registers `slow` and `gpu` once and skips `gpu` tests without CUDA; no `sys.path` edits. The analysis stream's path hack is dropped (the editable install makes it unnecessary) and the model stream's markers/skip hook moved out of `tests/model_stream/conftest.py`, which keeps only its fixtures. Marker text: "more than 30 s" (model/eval wording) instead of "more than a few seconds" (analysis).
- I-D003 **`checkpoint` in the probe table is the optimiser step** (int) read from the `epoch_<EEE>.pt` metadata, `init` for the untrained model. The analysis stream treats it as a step; epoch numbers would also order correctly but the step is what its learning curves plot.
- I-D004 **Batched prefetch in the probe harness** (`slm.eval.probes.prefetch`): when the scorer has `score_details(pairs)` the 36 cells of a group are scored in one call. Pure speed-up, tested equal to one-by-one scoring within 1e-3 (bf16-free CPU, batch padding noise). Touches eval-stream code on purpose; a scorer without the method behaves as before.
- I-D005 **QA table: `exact_value_match` is the primary outcome, aliased to the analysis name `exact_match`** (`QA_ALIASES`), so the model stream's column name survives into `qa.csv`. `model` is derived from (checkpoint label, prompt_mode); any other pair raises. `sft_val` facts are refused (they are never evaluated).
- I-D006 **MOCK banner.** `slm.analysis.banner` with labels SIMULATED and MOCK; `--banner-label` on `run_analysis.py` / `build_report.py`. The mock pipeline has no `--real` path (argparse error, exit 2) and never passes `--real` downstream. Banner text on report and figures: "MOCK DATA - NOT RESULTS".
- I-D007 **Realized diversity mapping.** The real `data/bank/realized_diversity.csv` has `core_unique_share, mean_pair_skeleton_jaccard, mean_pair_core_jaccard, mentions, prefixes`; the analysis expects `core_uniqueness, mean_pairwise_jaccard`. Mapped skeleton Jaccard -> mean_pairwise_jaccard (the analysis defines it as skeleton 3-gram Jaccard). **Unsure**: confirm with the bank owner that `mean_pair_skeleton_jaccard` is that quantity. Extra columns are kept.
- I-D008 **`sft_split` source.** Default is the KB's `sft_split` (sft_train -> train, heldout -> heldout). The mock QA file was built from `data/sft_mock/fact_split.json`, whose split differs from the KB's, so the mock run passes `--fact-split`. A real run must use the split the SFT data were built from; `tables_summary.json` does not record it (todo for the corpus-time run).
- I-D009 **Exposure source.** Measured counts from the manifest's train files when `--manifest` is given; else `--exposure` CSV; else planned counts from `plan.jsonl` (equal to KB `planned_mentions`, tested). The mock run uses planned counts, because the toy corpus mentions no KB value; `tables_summary.json` records `exposure_source`.
- I-D010 **Fact-level rule documentation.** The rule stays "more than half" (A-D023). For the real 3 test probes this is 2 of 3, identical to "at least half" (ceil(3/2) = 2). For even n the code is stricter than "at least half"; stated in INTERFACES.md and tested for n = 3, 4, 5. The count comes from the table, not a constant (the user asked to check this: `apply_rule` takes the share of stored probes).
- I-D011 **Report samples.** Classified by `report_inputs.classify` (success / entity confusion / repetition loop / format drift / wrong fact), taken from SFT answers on E2 and from greedy continuations of canonical prefixes at every saved checkpoint of seed 0. The taxonomy is mine (DESIGN 6 lists four failure categories: wrong fact, entity confusion, repetition loop, format drift); thresholds (trigram 3 times, one word 4 times in a row) are not tuned.
- I-D012 **Spec documents are missing.** `docs/Term_Project.pdf` and `docs/SPEC_COMPLIANCE.md` exist in no worktree or branch; `docs/SPLIT_MANIFEST.md` exists (model stream). Report outline and the 5-7 page limit stay from the task text. Nothing could be checked against the spec.
- I-D013 **spec-stream branch** is an ancestor of main (its last commit 7e33a51 is old data-stream work, 366 files behind main), so there was nothing to merge from it.
- I-D014 **Mock run skips the sweep** (`n_sweep_configs: 0` in run_facts) and uses 2 seeds, 8 epochs, batch 8; `--limit` questions per eval set (40 default; report-back run used 40).
- I-D015 **Merge conflicts** were limited to `AI_USE.md` (kept all lines; duplicates were different rows) and `tests/conftest.py` (add/add); `pyproject.toml` and `track.txt` merged cleanly because no stream touched them (each stream kept its own `track_*.txt`). See the report back.

## R00 (real-run preparation)
- I-D016 **Probe rendering audit with the real KB.** All 120 facts x 4 wordings (480 prompts) are rendered and checked for: a/an agreement, doubled words, capital first letter, no edge/double whitespace, no placeholder left, entity present, value absent (`tests/test_r00_rendering.py`, `scripts/render_probe_audit.py`). The mechanical checks found **no** defect in the old wording. Reading the 80 templates found two: (1) `species_min_age_weeks` n3 rendered "The youngest a cat may be to travel is", now "The youngest age at which a cat may travel is"; (2) `skyport_relief_gate` n3 ended "Head to" before a value that is a bare code, now "Head to gate" (same pattern as the other gate probes). Both are novel wordings, so the val/test sets change; nothing has been scored on the real corpus yet, so nothing is invalidated. A checker cannot see grammar like (1); only reading did.
- I-D017 **a/an helper.** Templates no longer type "a {e}": `{a_e}` / `{A_e}` render "a cat" / "an owl" through `slm.eval.wording.article` (first letter, with exceptions: hour/honest/heir take "an", uni-/use/eu-/one take "a"); `render` also collapses whitespace and capitalises the first letter. SFT question templates use `entity_ref` (same helper). `ENTITY_REF` moved to `wording.py` (still importable from `slm.eval.probes`). **The real KB has no vowel-initial entity**, so there is no "an" case in the 120 facts: the report shows three synthetic ones, labelled. The KB's own `canonical_sentence` / `canonical_prefix` are written by `scripts/build_kb.py` with a typed "a"; they are correct for the six species, and a test checks them, but a future vowel species would need that script changed (not touched: data stream).
- I-D018 **SFT / QA files from the KB's `sft_split`** (`scripts/build_sft_data.py`, `slm.sft.build.write_real_datasets/verify_datasets`): `data/sft/{sft_train,sft_val}.jsonl`, `data/sft/fact_split.json`, `data/eval/qa_test.jsonl` (E0 336, E1 144, E2 180 rows; SFT 336 + 24), manifest with sha256 in `data/sft/manifest.json`. 14 assertions are re-run by `run_all_mock.py` and by the orchestrator (`sft` and `qa_eval` stages). **Correction to I-D008:** `data/sft_mock/fact_split.json` is identical to the KB's `sft_split` (0 of 120 differ), so the statement that the mock QA file used a different split does not reproduce; I cannot say why the earlier mock run needed `--fact-split`. The mock now reads the same files as the real run.
- I-D019 **Orchestrator** `scripts/run_real.py` + `configs/real.yaml` (+ `configs/real_mock.yaml` for the dry run): 12 stages, one JSON stage report each under `<out>/stages/`, skipped when ok for the same config hash, `--force`, `--only/--from/--until`, `--list`; running a stage deletes the reports of all later stages. Output under `runs/real/`. Real mode stops with a message if the corpus manifest is missing.
- I-D020 **Final epochs = best epoch of the winning sweep/sizing run** (PREREG D4: "a fixed number of epochs chosen on validation loss in the sweep"), the final seeds train a cosine schedule of that length with the log-spaced checkpoint schedule cut at it. **Deviation from docs/HPARAM_PROTOCOL.md section 3.4** (final = full 20 epochs, best epoch informational). The two documents disagree; I followed the later one (PREREG v3) and the user's wording. The sweep schedule (20 epochs, cosine) is not the final schedule, so the best epoch is a proxy; unsure whether the owner wants a re-fit.
- I-D021 **Sizing check** (DESIGN section 5): the ~25M model is 8 layers / 8 heads / d_model 512 / d_ff 2048 (`model_large`), trained once with the sweep's chosen lr and dropout, same epochs and tokens, seed 0; the winner is the lower best validation loss; no probes. The large model's lr is not re-tuned (one extra grid would be 9 more runs). DESIGN also says "and val-probe accuracy"; not used here (val probes would be a probe read before the freeze).
- I-D022 **Freeze** (`scripts/freeze_prereg.py`, `slm.integration.freeze`): appends a marked block to the PREREG file with sha256 of the file without the block, git commit/branch/dirty flag, hash of the analysis code, UTC time; `verify` recomputes it. Refuses if the ledger has any entry, any `probe*.csv` under the run dir has a test-split row, or any `qa_predictions*.csv` exists. A second run on a frozen file only verifies. Later stages (`pretrain`, `probes`, `sft`, `qa_eval`, `report`) call `verify` and stop if the file was edited. The dirty flag is recorded, not enforced.
- I-D023 **Test probes go through the ledger.** Probes are wording, not files, so `open_split` never sees them; `slm.guard.record_test_use` writes a ledger line (purpose, git, caller, KB hash) before the probe stage scores anything. The QA stage reads the test file through `open_split` as before. Real ledger: `reports/test_access_log.jsonl`; the mock dry run keeps its own inside its output dir.
- I-D024 **Stats stage** writes tokens/word, share of docs over 512 tokens and tokens for train and val; the **test split token count is null on purpose** (counting it would be a test read before the freeze).
- I-D025 **`init` probes** use `untrained_model(cfg, seed)` with the selected architecture and dropout (the same initial draw as `train_run`); the stage summary records `has_init`.

## R01 (taxonomy, ranking accuracy, exemplars, samples, README)
- I-D026 **Spec files not in the repo.** `docs/Term_Project.pdf` and `docs/SPEC_COMPLIANCE.md` were absent; step 0 was skipped on the user's instruction ("the architect holds them"). R01 follows DESIGN 7.2, 7.4, 9(g) and the spec points the user relayed (6/R19, 7/risk 3, 9(f)/risk 5, 9(g), 9(d), 9(j)); nothing was checked against the spec text itself. Also: the exemplar deviation row (DESIGN_CHANGES row 22) now cites this id.
- I-D027 **Error taxonomy** (`slm.sft_eval.taxonomy`, `docs/ERROR_TAXONOMY.md`): exactly one class per prediction, decided in a fixed order (correct; empty/repetition; right-type wrong-value; no value-like string; hallucination). Value-like strings are extracted by one rule per KB value class (11 classes, 20 attributes). Choices that are mine: (a) "right type" means the KB value **class**, so a form code for a gate question is right-type wrong-value; (b) a value of the **wrong** class only (a name for a fee) is a format failure, an extension of "no value-like token at all", to keep the four classes exhaustive; (c) names are 2-3 capitalised words minus sentence openers, entity names and other-class KB values, so a capitalised noun phrase can be read as a hallucinated name; (d) repetition = one 1-3 word n-gram covering more than 50% of at least 4 words. 97 tests (every class x every attribute).
- I-D028 **`error_class` and the rank columns are optional evaluator columns** (added when `taxonomy=` / `ranking=True` is passed), carried into `qa.csv` when present; `error_taxonomy.csv` and `ranking_accuracy.csv` are written next to it. The mock pipeline and the orchestrator turn both on.
- I-D029 **Ranking accuracy.** DESIGN section 6: "Ranking accuracy / MRR: log p(value | prompt) vs all same-type values; summed and length-normalized log-probs both reported"; section 7.4 only names it. Implemented as that definition under the QA prompt (with the 2-shot prefix for that variant) for the 6 values of the attribute: `rank_value` (summed) and `rank_value_norm` (per token) for the continuation `" " + value`. **Added** `rank_sentence` and `rank_sentence_norm` (the gold answer sentence with the value swapped) because SFT answers are sentences and a bare value after `Answer:` is out of distribution for the SFT model; both are reported, the DESIGN one is `rank_value`. Ties never rank 1.
- I-D030 **2-shot exemplars.** Re-picked from the real `data/sft/sft_val.jsonl` / `data/eval/qa_test.jsonl` with `choose_base_exemplars.py` (new `--eval-dir`): F049 (airship_onboard_handler_name, Halcyon) and F064 (species_max_combined_weight, rabbit), identical to the existing config, because the "mock" SFT files were the real split (see the I-D018 correction). The config comment calling them mock-split ids was wrong. Deviation from DESIGN 7.2 (exemplars from SFT-train facts) kept and logged: SFT-train facts are E0/E1 facts. `tests/test_r01_exemplars.py`.
- I-D031 **Sample generator** (`slm.integration.samples`, `scripts/sample_checkpoints.py`, orchestrator stage `samples`). Prompt list built from the KB (round-robin over the six cells, seeded), first 10 = 5 canonical + 3 novel + 2 off-domain, 20 = those plus 5 + 3 + 2 more. Completion = first sentence of 32 new tokens. Flags use the taxonomy (value_correct, wrong_value, hallucinated, gibberish; off-domain: gibberish or off_domain_ok). Selection: round-robin over checkpoints in training order, a different prompt each time where possible; **not padded** when fewer than 6 successes exist (the Markdown says so). The prompts are canonical prefixes and novel wordings of KB facts, so a real run writes a ledger line (`record_test_use`); the `samples` stage needs a valid freeze.
- I-D032 **`generate.py` console crash fixed.** The README test found that `scripts/generate.py` died with `UnicodeEncodeError` on a Windows cp1252 console when the model emitted a byte sequence that decodes to U+FFFD; stdout/stderr are now reconfigured to UTF-8 with `errors="replace"`. This is a demo-day risk (spec 9(j)).
- I-D033 **README** is `docs/README.md` (the root README stays a stub with a pointer). It keeps `<...>` placeholders for numbers that need the real run. The test reads the code blocks: every `python scripts/...` exists, every `generate.py` command runs on a mock bundle on CPU (interactive fed `:quit`), `--help`/`--list` commands exit 0, the stage list equals `run_real.STAGES`.
