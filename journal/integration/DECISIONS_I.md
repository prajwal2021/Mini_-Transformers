# Integration decisions (I-D###)

- I-D001 **Separate venv for this worktree.** `.venv` (gitignored) is a venv whose `site-packages` has a `.pth` pointing at the main checkout's `.venv\Lib\site-packages` (torch cu128, pandas, statsmodels, pytest, ruff ...), plus `pip install -e . --no-deps` from this worktree. `slm` therefore resolves to `slm-integration/src` (checked: `slm.__file__`, `pip show` editable location). Reason: the main venv's editable install points at the main checkout, Window 1 keeps running P02c from it, and re-installing there would repoint it. Cost: dependency versions follow main's venv.
- I-D002 **One `tests/conftest.py`.** Registers `slow` and `gpu` once and skips `gpu` tests without CUDA; no `sys.path` edits. The analysis stream's path hack is dropped (the editable install makes it unnecessary) and the model stream's markers/skip hook moved out of `tests/model_stream/conftest.py`, which keeps only its fixtures. Marker text: "more than 30 s" (model/eval wording) instead of "more than a few seconds" (analysis).
- I-D003 **`checkpoint` in the probe table is the optimiser step** (int) read from the `epoch_<EEE>.pt` metadata, `init` for the untrained model. The analysis stream treats it as a step; epoch numbers would also order correctly but the step is what its learning curves plot.
- I-D004 **Batched prefetch in the probe harness** (`slm.eval.probes.prefetch`): when the scorer has `score_details(pairs)` the 36 cells of a group are scored in one call. Pure speed-up, tested equal to one-by-one scoring within 1e-3 (bf16-free CPU, batch padding noise). Touches eval-stream code on purpose; a scorer without the method behaves as before.
- I-D005 **QA table: `exact_value_match` is the primary outcome, aliased to the analysis name `exact_match`** (`QA_ALIASES`), so the model stream's column name survives into `qa.csv`. `model` is derived from (checkpoint label, prompt_mode); any other pair raises. `sft_val` facts are refused (they are never evaluated).
- I-D006 **MOCK banner.** `slm.analysis.banner` with labels SIMULATED and MOCK; `--banner-label` on `run_analysis.py` / `build_report.py`. The mock pipeline has no `--real` path (argparse error, exit 2) and never passes `--real` downstream. Banner text on report and figures: "MOCK DATA - NOT RESULTS".
- I-D007 **Realized diversity mapping.** The real `data/bank/realized_diversity.csv` has `core_unique_share, mean_pair_skeleton_jaccard, mean_pair_core_jaccard, mentions, prefixes`; the analysis expects `core_uniqueness, mean_pairwise_jaccard`. Mapped skeleton Jaccard -> mean_pairwise_jaccard (the analysis defines it as skeleton 3-gram Jaccard). **Unsure**: confirm with the bank owner that `mean_pair_skeleton_jaccard` is that quantity. Extra columns are kept.
- I-D008 **`sft_split` source.** Default is the KB's `sft_split` (sft_train -> train, heldout -> heldout). The mock QA file was built from `data/sft_mock/fact_split.json`, whose split differs from the KB's, so the mock run passes `--fact-split`. A real run must use the split the SFT data were built from; `tables_summary.json` does not record it (todo for the corpus-time run).
- I-D009 **Exposure source.** Measured counts from the manifest's train files when `--manifest` is given; else `--exposure` CSV; else planned counts from `plan.jsonl` (equal to KB `planned_mentions`, tested). The mock run uses planned counts, because the toy corpus mentions no KB value; `tables_summary.json` records `exposure_source`.
- I-D010 **Fact-level rule documentation.** The rule stays "more than half" (A-D023). For the real 3 test probes this is 2 of 3, identical to "at least half" (ceil(3/2) = 2). For even n the code is stricter than "at least half"; stated in INTERFACES.md and tested for n = 3, 4, 5. The count comes from the table, not a constant (the user asked to check this: `apply_rule` takes the share of stored probes).
- I-D011 **Report samples.** Classified by `report_inputs.classify` (success / entity confusion / repetition loop / format drift / wrong fact), taken from SFT answers on E2 and from greedy continuations of canonical prefixes at every saved checkpoint of seed 0. The taxonomy is mine (DESIGN 6 lists four failure categories: wrong fact, entity confusion, repetition loop, format drift); thresholds (trigram 3 times, one word 4 times in a row) are not tuned.
- I-D012 **Spec documents are missing.** `docs/Term_Project.pdf` and `docs/SPEC_COMPLIANCE.md` exist in no worktree or branch; `docs/SPLIT_MANIFEST.md` exists (model stream). Report outline and the 5-7 page limit stay from the task text. Nothing could be checked against the spec.
- I-D013 **spec-stream branch** is an ancestor of main (its last commit 7e33a51 is old data-stream work, 366 files behind main), so there was nothing to merge from it.
- I-D014 **Mock run skips the sweep** (`n_sweep_configs: 0` in run_facts) and uses 2 seeds, 8 epochs, batch 8; `--limit` questions per eval set (40 default; report-back run used 40).
- I-D015 **Merge conflicts** were limited to `AI_USE.md` (kept all lines; duplicates were different rows) and `tests/conftest.py` (add/add); `pyproject.toml` and `track.txt` merged cleanly because no stream touched them (each stream kept its own `track_*.txt`). See the report back.
