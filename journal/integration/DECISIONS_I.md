# Integration decisions (I-D###)

- I-D001 **Separate venv for this worktree.** `.venv` (gitignored) is a venv whose `site-packages` has a `.pth` pointing at the main checkout's `.venv\Lib\site-packages` (torch cu128, pandas, statsmodels, pytest, ruff ...), plus `pip install -e . --no-deps` from this worktree. `slm` therefore resolves to `slm-integration/src` (checked: `slm.__file__`, `pip show` editable location). Reason: the main venv's editable install points at the main checkout, Window 1 keeps running P02c from it, and re-installing there would repoint it. Cost: dependency versions follow main's venv.
- I-D002 **One `tests/conftest.py`.** Registers `slow` and `gpu` once and skips `gpu` tests without CUDA; no `sys.path` edits. The analysis stream's path hack is dropped (the editable install makes it unnecessary) and the model stream's markers/skip hook moved out of `tests/model_stream/conftest.py`, which keeps only its fixtures. Marker text: "more than 30 s" (model/eval wording) instead of "more than a few seconds" (analysis).
- I-D003 **`checkpoint` in the probe table is the optimiser step** (int) read from the `epoch_<EEE>.pt` metadata, `init` for the untrained model. The analysis stream treats it as a step; epoch numbers would also order correctly but the step is what its learning curves plot.
- I-D004 **Batched prefetch in the probe harness** (`slm.eval.probes.prefetch`): when the scorer has `score_details(pairs)` the 36 cells of a group are scored in one call. Pure speed-up, tested equal to one-by-one scoring within 1e-3 (bf16-free CPU, batch padding noise). Touches eval-stream code on purpose; a scorer without the method behaves as before.
- I-D005 **QA table: `exact_value_match` is the primary outcome, aliased to the analysis name `exact_match`** (`QA_ALIASES`), so the model stream's column name survives into `qa.csv`. `model` is derived from (checkpoint label, prompt_mode); any other pair raises. `sft_val` facts are refused (they are never evaluated).
- I-D006 **MOCK banner.** `slm.analysis.banner` with labels SIMULATED and MOCK; `--banner-label` on `run_analysis.py` / `build_report.py`. The mock pipeline has no `--real` path (argparse error, exit 2) and never passes `--real` downstream. Banner text on report and figures: "MOCK DATA - NOT RESULTS".
- I-D007 **Realized diversity mapping.** The real `data/bank/realized_diversity.csv` has `core_unique_share, mean_pair_skeleton_jaccard, mean_pair_core_jaccard, mentions, prefixes`; the analysis expects `core_uniqueness, mean_pairwise_jaccard`. Mapped skeleton Jaccard -> mean_pairwise_jaccard (the analysis defines it as skeleton 3-gram Jaccard). **Unsure**: confirm with the bank owner that `mean_pair_skeleton_jaccard` is that quantity. Extra columns are kept.
- I-D008 **`sft_split` source.** Default is the KB's `sft_split` (sft_train -> train, heldout -> heldout). The mock QA file was built from `data/sft_mock/fact_split.json`, whose split differs from the KB's, so the mock run passes `--fact-split`. A real run must use the split the SFT data were built from; `tables_summary.json` does not record it (todo for the corpus-time run).
- I-D009 **Exposure source.** Measured counts from the manifest's train files when `--manifest` is given; else `--exposure` CSV; else planned counts from `plan.jsonl` (equal to KB `planned_mentions`, tested). The mock run uses planned counts, because the toy corpus mentions no KB value; `tables_summary.json` records `exposure_source`.

For even n the code is stricter than "at least half"; stated in INTERFACES.md and tested for n = 3, 4, 5. The count comes from the table, not a constant (the user asked to check this: `apply_rule` takes the share of stored probes).

## R01 (taxonomy, ranking accuracy, exemplars, samples, README)

- I-D027 **Error taxonomy** (`slm.sft_eval.taxonomy`, `docs/ERROR_TAXONOMY.md`): exactly one class per prediction, decided in a fixed order (correct; empty/repetition; right-type wrong-value; no value-like string; hallucination). Value-like strings are extracted by one rule per KB value class (11 classes, 20 attributes). Choices that are mine: (a) "right type" means the KB value **class**, so a form code for a gate question is right-type wrong-value; (b) a value of the **wrong** class only (a name for a fee) is a format failure, an extension of "no value-like token at all", to keep the four classes exhaustive; (c) names are 2-3 capitalised words minus sentence openers, entity names and other-class KB values, so a capitalised noun phrase can be read as a hallucinated name; (d) repetition = one 1-3 word n-gram covering more than 50% of at least 4 words. 97 tests (every class x every attribute).

## R03 (E* rule, warmup scaling, PREREG v4)
- I-D039 **Why the budget rule changes.** R02 measured a full-size train split of about 0.75M tokens (about 45 optimiser steps per epoch at batch 32). On a corpus that small validation loss bottoms out after few epochs (overfitting) while fact storage (the quantity the study is about) keeps improving; DESIGN section 5 selects checkpoints by the VALIDATION PROBES, and R00's I-D020 / PREREG v3 D4 used validation loss. The budget is therefore chosen by validation-probe stored rate, with validation loss only as the tie-break. Validation probes are the 2 val wordings per fact (canonical + one novel), never test.
- I-D040 **The rule as implemented** (`slm.train.budget.select_budget`, tolerance 0.01): config score = best val-probe stored rate over the schedule (probe level, mean of `stored`, 240 rows = 120 facts x 2 probes, so one probe is 0.0042 and the tolerance is about 2.4 probes); near-ties = configs within 0.01 of the best score; winner = lowest minimum validation loss among them (first in grid order on an exact tie); E* = earliest checkpoint of the winner within 0.01 of its own best. The val-loss-optimal epoch of the winner is returned and printed beside E*. `init` (untrained model of the seed) and `null_stored_rate` are recorded per config as the chance reference. The sweep deletes each config's checkpoints after scoring them (12 configs x 13 checkpoints would be 156 files); the decision table is `reports/tables/sweep_decision.md` (real) and `runs/real_mock/sweep_decision.md` (mock).
- I-D041 **Final runs.** One run per seed trains for 2E* epochs (cap 60) with the chosen config and saves E*, 2E* and the schedule. Primary analysis, SFT start (`run_sft_seeds(pretrain_epoch=E*)`), QA base models and `stored_pretrain` use the checkpoint of E*: the primary analysis table is the probe table cut at the E* step (`build_analysis_tables --max-step`), so E* is every seed's final checkpoint for the unchanged analysis code. The secondary analysis (H1/H2 at 2E*, probe hypotheses only, no QA) runs on the full table into `results_secondary/`. **Limitation:** the sweep's cosine spans 60 epochs and the final run's spans 2E*, so E* is a proxy for the budget; I did not train a second E*-long run per seed (twice the compute) and flagged it in PREREG section 9.
- I-D042 **Sizing check by the same rule.** The chosen config is trained at ~25M parameters (8/8/512) with the same schedule; `select_budget` picks small or large from the two curves (the winner's E* is used). DESIGN's "val loss and val-probe accuracy" is now followed; I-D021's val-loss-only comparison is superseded.
- I-D043 **Step-scaled schedule** (`TrainConfig.resolve`, called in `train_run`; `configs/train.yaml` is the single source): warmup = 5% of total steps (floor 10, ceiling half the run), `val_every = total // 40`, `log_every = total // 200`; `warmup_steps/val_every/log_every` stay as fallbacks when the per-run fields are null (so older tests and `m02`/`m04` scripts are unchanged). `steps_per_epoch`, `total_steps` and the resolved values are in each run's `summary.json` and printed by the sweep stage. Mock configs lost their hand-set warmup/val intervals.
- I-D044 **PREREG v4** (docs/PREREG.md, still `NOT FROZEN`): title v4; margins final and stated as researcher-chosen, not data-derived (code constants unchanged: log 1.25 = 0.223, 0.10; the decision string no longer says "placeholder"); D4 rewritten (E* by validation probes, 2E* secondary); section 4 gains the chance-baseline bullet and the new checkpoint bullet; section 7 gains the interpretation-of-nulls paragraph; section 9 is the full budget rule; the freeze-record hash and analysis-commit placeholders are untouched. `tests/test_r03_prereg.py` ties the text to the constants.
- I-D045 **Freeze** records `config_sha256`, the config file, E*, total epochs, model size, lr, dropout, batch size and the val-loss-optimal epoch next to the PREREG hash and git state (`--config`, `--final-config` on the CLI; the orchestrator passes them). It refuses when the ledger has any test-split entry (an unreadable line counts), a test-split probe row or QA test predictions exist; non-test ledger lines do not block.
- I-D046 **Housekeeping.** `slm.train.sweep` (the val-loss-only sweep) is kept but no longer used by the orchestrator; `scripts/partial_dryrun.py` was adapted to the new sweep layout (no checkpoints are kept, so it prints no samples any more).
- I-D047 **Separate sweep seed (100).** Evidence (R03 report, unsure 1): the sweep's seed 0 was also a final seed and val/test canonical probes share a prompt, so E* partly selected on an outcome a test probe repeats. The sweep now uses seed 100 (`slm.train.budget.SWEEP_SEED`, `sweep.seed` in all three configs); `run_budget_sweep` and `st_sweep` raise if it is a final seed; `tests/test_r04_budget.py` checks all configs. Supersedes I-D039..I-D042 on seed use.
- I-D048 **E* rule v2.** Evidence (R03 unsure 2 and the mock table: every stored rate 0.058-0.117 against init 0.108, rule picked E*=1 on noise): 240 val probes give SE ~0.02, above the 0.01 tolerance, and a max over 12 x 13 cells is biased up. New rule (`slm.train.budget.select_budget`): centred 3-checkpoint moving average (shortened at the ends), SE = mean of the window's fact-clustered SEs (conservative: checkpoints are correlated); config score = best smoothed rate; near-ties within 1 SE to the lower validation loss; E* = earliest checkpoint within 1 SE of the config's best smoothed rate; CHANCE GUARD: best smoothed <= init + 2 SE -> E* = epoch of minimum validation loss, flag `no_val_storage`, WARNING in the decision table. Fact-clustered SE from the probe rows (`fact_se`); binomial from `n_probes` as fallback. Unit tests: plateau start, at-chance guard, determinism.
- I-D049 **Identical schedule.** Evidence (R03 unsure 3): the sweep's cosine spanned 60 epochs, the final run's 2E*, so E* was a proxy. The final seeds now train for the sweep's epoch count with the sweep's checkpoints (`st_sizing` writes `epochs = sweep.epochs`); `final_schedule` and all 2E* wording are removed (PREREG, orchestrator, tests assert it). Primary analysis, SFT start and `stored_pretrain` at E*; the secondary analysis (outside Holm) is epoch 60 (`analysis_inputs_secondary`, `results_secondary`); the schedule sha256 is in `final_config.json` and the freeze.
- I-D050 **Two-stage sweep with an ETA.** Stage 1: 6 configs at batch 32; stage 2: the best stage-1 config (by the same rule) at batch 16 (7 runs); `sizing` then runs the chosen config at 27.6M. After the first run: `projected_hours = first_run_seconds x (n_stage1 + n_stage2 + large_factor) / 3600` (large_factor = param ratio), printed and written to `sweep/eta.json`; `SweepTooLong` aborts above `sweep.max_hours` (3). Assumption: every run costs about the first one; the large model costs its parameter ratio times as much.
- I-D051 **Freeze refuses a dirty git tree** (tracked files; the PREREG file itself excepted; untracked files are not counted) and records the clean commit hash. `require_clean=False` / `--allow-dirty` exist for mock runs (the orchestrator passes `not c.mock`) and for the pre-R04 tests. The R00 dry run recorded `dirty: true`; that can no longer happen in a real freeze.
- I-D052 **Real-mode report gate.** `scripts/build_report.py --real` now requires `--prereg` (default docs/PREREG.md) to carry a verified freeze record; otherwise exit 3 and nothing is built. `scripts/real_report_path_test.py` exercises it on a scratch repo with mock content (stamped PATH TEST, NOT RESULTS); `tests/test_r04_budget.py` has the fast version. Note: `run_analysis.py --real` has no such gate (the orchestrator calls it only after `require_freeze`).
- I-D053 **QA cost measured** (`scripts/measure_qa_cost.py`, SFT validation questions only, the test file is never opened): 0.14-0.16 s per generated answer and 0.008 s per ranked question on the RTX 5080 laptop GPU for the 12.4M model; projection for 660 x 3 x 3 = 5,940 answers about 16 min < 40 min, so NO batched decoder was added (the rule asked for one only above 40 min). Caveat: timed on a mock checkpoint (outputs probably run to the 48-token cap, so this is an upper bound for a trained model) with 72 timed answers (the 24 val questions repeated).
